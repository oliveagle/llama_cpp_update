# HIP (ROCm) 加载问题 - 最终诊断报告

> **生成时间**: 2026-02-17
> **状态**: 问题未解决，需要上游修复

---

## 一、测试方案汇总

| 方案 | 结果 | 说明 |
|------|------|------|
| mmap ON | ❌ 失败 | 卡住 90s+ |
| mmap OFF | 未测试 | 预计相同 |
| 小模型 (0.6B) | ❌ 失败 | 358MB 仍卡住 |
| gfx1100 兼容模式 (7.12) | ❌ 失败 | 相同问题 |
| ROCm 7.2.0 | ❌ 失败 | 相同问题 |
| HIP Graphs 启用 | ❌ 失败 | 编译成功但运行相同 |
| --fit off | ✅ 必要 | 避免内存适配卡住，但不解决加载慢 |

---

## 二、问题定位

### 2.1 卡住的准确位置

```
✅ GGUF 解析
✅ 张量加载到 GPU (offloaded 29/29 layers)
✅ GPU 内存分配 (358MB)
❌ 初始化完成 (model loaded)  <-- 卡在这里
```

### 2.2 关键发现

- **不是 mmap 问题**: 相同位置卡住
- **不是模型大小问题**: 0.6B 小模型相同
- **不是 ROCm 版本问题**: 7.12 和 7.2.0 相同
- **不是 GPU 架构问题**: gfx1100 覆盖相同
- **可能是 llama.cpp HIP 后端问题**: 需要 ggml-org 修复

---

## 三、根本原因推测

### 最可能原因: llama.cpp HIP 后端 bug

**证据**:
1. 所有环境测试都卡在相同位置
2. ROCm 能识别设备、分配内存、加载数据
3. 问题出现在 "load_tensors" 完成后
4. 可能是 backend 初始化或 stream 同步问题

**可能的具体问题**:
- ggml-hip 后端初始化死锁
- kernel launch 后同步卡住
- memory pool 初始化问题
- ROCm 7.x + gfx1151 特定组合问题

---

## 四、建议行动

### 4.1 短期 (现在)

**使用 Vulkan 后端 (8400)**
- 稳定、加载快、性能可接受 (66 tps)
- 推荐配置: ctx-size = 8192

### 4.2 中期 (等待)

**跟踪 llama.cpp 更新**
- 关注 ggml-org/llama.cpp HIP 相关 PR
- 测试新版本发布

**参考 Issue**:
- https://github.com/ggml-org/llama.cpp/issues (搜索 HIP, gfx1151)

### 4.3 长期 (反馈)

**向 AMD 反馈**
- ROCm gfx1151 支持问题
- Strix Halo APU 特定问题

---

## 五、最终结论

| 项目 | 结论 |
|------|------|
| HIP 可用性 | ❌ 当前不可用 (加载卡住) |
| 推荐后端 | ✅ Vulkan (8400) |
| 备用后端 | ✅ CUDA (8401, V100) |
| 等待修复 | ⏳ llama.cpp / ROCm 更新 |

**总结**: HIP 问题非配置/环境原因，是 llama.cpp HIP 后端与 gfx1151/ROCm7.x 的兼容性问题。建议使用 Vulkan 直至上游修复。

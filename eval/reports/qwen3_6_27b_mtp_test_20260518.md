# Qwen3.6-27B-MTP 测试报告

> **日期**: 2026-05-18
> **状态**: 测试失败 - 显存不足

## 概述

尝试测试 Qwen3.6-27B-MTP 模型的 Multi-Token Prediction (MTP) 功能，但由于 GPU 显存不足未能完成测试。

## 环境

| 项目 | 值 |
|------|-----|
| AMD GPU | Radeon 8060S Graphics (gfx1151) |
| AMD 显存 | 32GB（部分已被占用） |
| llama.cpp | b9196 (Vulkan) |
| 量化格式 | Q4_K_M |
| 模型文件 | Qwen3.6-27B-Q4_K_M.gguf (16.3 GB) |

## 测试结果

### 问题 1: 显存不足

- **现象**: `ggml_vulkan: Device memory allocation of size 1070249472 failed`
- **原因**: Qwen3.6-27B-Q4_K_M.gguf 文件大小 16.3GB，模型加载时需要约 20-25GB 显存（权重 + KV cache + 临时缓冲区）
- **影响**: 无法在单卡 AMD 上完全加载模型

### 尝试的方案

| 方案 | 结果 |
|------|------|
| `--n-gpu-layers 99` (全部上 GPU) | 失败：Vulkan 显存不足 |
| `--n-gpu-layers 30` (部分上 GPU) | 失败：仍然需要分配 1GB buffer 失败 |

### 问题分析

即使减少 GPU 层数，模型加载仍然需要为部分层分配 GPU 显存。AMD GPU 的 32GB 显存不足以加载 27B Q4_K_M 模型。

**可能原因**:
- 系统使用了集成显示输出，导致一部分系统内存被保留给显示，实际可用显存不足 32GB
- Vulkan buffer 分配策略较为严格，大模型连续内存分配容易失败
- 27B 模型即使 Q4_K_M 量化后仍然需要约 20GB+ 显存

## 下一步计划

### 方案 1: 使用 Qwen3.5-9B-MTP (推荐)
- **模型**: unsloth/Qwen3.5-9B-MTP-GGUF
- **量化**: Q4_K_M (5.47 GB) 或 IQ4_NL (5.26 GB)
- **显存需求**: ~8-12 GB，可以在 AMD 上运行
- **注意**: 需要网络下载

### 方案 2: 等待网络恢复后下载 Qwen3.5-4B-MTP
- **模型**: localweights/Qwen3.5-4B-MTP-BF16-GGUF
- **大小**: ~8.3 GB
- **显存需求**: ~10-12 GB

### 方案 3: 使用 CPU offload
- **方案**: 减少 `--n-gpu-layers` 到更小的值（如 10-15），大部分模型放在 CPU
- **缺点**: 速度会很慢（< 1 t/s）

⚡ Stage 1: 性能/吞吐量测试

测试目的

测量模型的响应速度、token 生成速率和上下文扩展能力，验证模型在特定硬件上的可用性。

测试指标

指标 说明 单位 通过标准
首 token 延迟 (TTFT) 从请求到首个 token 返回的时间 ms < 500ms
生成速率 (TPS) 每秒生成的 token 数量 t/s > 30 t/s
预填充速度 Prompt 处理速度 t/s > 100 t/s
上下文支持 最大可处理的上下文长度 tokens ≥ 4K

Context 测试层级

层级 Token 数量 预期结果 说明
4K 4096 必须通过 基础上下文
8K 8192 推荐通过 标准上下文
16K 16384 可选测试 长上下文
32K 32768 可选测试 超长上下文
64K+ 65536+ 扩展测试 极限测试

测试方法

大海捞针 (Needle in a Haystack): 在长上下文的特定位置插入关键信息，要求模型回忆该信息，验证信息保留率。

📖 测试结果解读指南

如何阅读测试报告

1. 先看综合得分：综合得分反映模型整体能力，≥85%为优秀，70-84%为良好，60-69%为及格，<60%为不及格。
2. 分析维度得分：查看各维度得分，找出模型的优势和短板，根据使用场景选择合适的模型。
3. 对比同类模型：同一家族的模型通常有相似的特点，对比不同家族的模型可以找到最适合的选项。

常见结果模式

模式 特征 代表模型 适用场景
全能型 各维度得分均衡且高 Qwen3-VL-8B 通用任务
代码专家 代码满分，数学较弱 Qwen3系列 编程辅助
数学专家 数学强，其他均衡 GLM-4家族 数学推理
大模型 理解能力强，资源占用大 JoyAI-LLM-Flash 深度理解
小模型 资源占用小，能力有限 Qwen3-0.6B 边缘设备
